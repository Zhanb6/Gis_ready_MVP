# Запуск в закрытой локальной сети

## 1. Схема работы

- На одном компьютере или сервере запускаются четыре контейнера: LAN-шлюз, веб-приложение, PostgreSQL и Ollama.
- Рабочие места открывают веб-приложение по IP сервера, например `http://10.18.2.54:3000`.
- Все браузеры обращаются к одному приложению, а приложение использует один Docker volume PostgreSQL.
- Наружу публикуется только TCP-порт `3000` LAN-шлюза. Шлюз проксирует запросы только на фиксированный внутренний адрес веб-приложения.
- PostgreSQL и Ollama доступны только приложению внутри закрытой Docker-сети `offline-data` с параметром `internal: true`.
- LAN-шлюз связан с приложением через отдельную внутреннюю сеть `app-ingress` и не подключён к сети данных. Приложение не имеет внешнего маршрута.
- Экраны заявок, месячного плана и встречной логистики проверяют изменения каждые 5 секунд и обновляются после записи другого пользователя.

## 2. Что должно быть установлено

- Docker Engine с Docker Compose v2 или Docker Desktop.
- Локально загруженные образы `node:20-alpine`, `postgres:16-alpine` и `ollama/ollama:latest`.
- Для полноценного ИИ в volume Ollama должна находиться модель `mistral:7b-instruct-q4_0`.

Зависимости Node уже находятся в `vendor/node_modules`; во время сборки приложение не обращается к npm.

На полностью изолированный сервер Docker-образы необходимо перенести заранее. На подготовительном компьютере:

```bash
docker pull node:20-alpine
docker pull postgres:16-alpine
docker pull ollama/ollama:latest
docker save -o astanahub-docker-images.tar node:20-alpine postgres:16-alpine ollama/ollama:latest
```

На закрытом сервере:

```bash
docker load -i astanahub-docker-images.tar
```

## 3. Настройка

Перед первым запуском сгенерируйте уникальный локальный `.env`:

```bash
node tools/generate_env.js
```

Скрипт создаёт случайные логины и пароли для начальных ролей и случайный пароль PostgreSQL. Значения хранятся только в локальном `.env`, который исключён из Git. Не пересылайте весь файл и не публикуйте его.

Основные несекретные параметры:

```text
APP_PORT=3000
POSTGRES_DB=logistics_mvp
POSTGRES_USER=logistics
COOKIE_SECURE=false
```

Для HTTPS через доверенный обратный прокси установите `COOKIE_SECURE=true`. Пароль PostgreSQL используется только контейнерами и не является паролем пользователей веб-приложения.

### Изменения запуска сервера

Node.js использует переменную `HOST` и явно слушает все интерфейсы:

```js
const HOST = process.env.HOST || "0.0.0.0";
server.listen(PORT, HOST);
```

В Docker Compose для приложения и LAN-шлюза передаётся `HOST=0.0.0.0`. Все операции изменения общей базы проходят через серверную очередь, поэтому два одновременных запроса не перезаписывают изменения друг друга.

## 4. Запуск

Из каталога проекта:

```bash
test -f .env || node tools/generate_env.js
docker compose up -d --build
docker compose ps
```

У контейнеров `astana-logistics-lan-gateway`, `astana-logistics-mvp`, `astana-logistics-postgres` и `astana-logistics-ollama` должен быть статус `Up`. LAN-шлюз, PostgreSQL и приложение должны стать `healthy`.

Проверка на сервере:

```bash
curl http://127.0.0.1:3000/
```

Первый запуск автоматически создаёт схему PostgreSQL и начальные локальные справочники.

## 5. Как узнать IP сервера

Linux:

```bash
hostname -I
ip addr
```

Windows:

```powershell
ipconfig
```

Используйте значение `IPv4 Address` сетевого адаптера локальной сети.

macOS:

```bash
ipconfig getifaddr en0
ipconfig getifaddr en1
```

Нужен адрес локального адаптера, например `10.18.2.54`, а не `127.0.0.1`.

Желательно закрепить этот IP в DHCP или назначить серверу статический адрес.

## 6. Подключение пользователей

1. Сервер и рабочее место должны находиться в одной локальной сети и видеть друг друга.
2. В браузере рабочего места откройте `http://IP_СЕРВЕРА:3000`.
3. Для текущего сервера проверен адрес `http://10.18.2.54:3000`.
4. Войдите под своей учётной записью. Быстрый вход и публичная регистрация отсутствуют.

Пользователям не требуется устанавливать Node.js, PostgreSQL, Ollama или Docker.

## 7. Как проверить общую базу

Функциональная проверка:

1. На рабочем месте A войдите как инициатор и создайте заявку.
2. На рабочем месте B войдите под другой ролью и откройте список заявок.
3. После отправки заявки изменения появятся на другом рабочем месте автоматически, не позднее чем через 5 секунд.

Проверка на сервере:

```bash
docker compose exec -T postgres psql -U logistics -d logistics_mvp -c "select id, status, cargo_name, updated_at from applications order by length(id), id;"
```

Все рабочие места должны показывать данные из этой таблицы. Других backend-хранилищ в проекте нет.

## 8. Если сайт не открывается

1. На сервере выполните `docker compose ps`. Приложение и PostgreSQL должны быть `healthy`.
2. Проверьте локально `curl http://127.0.0.1:3000/`.
3. На рабочем месте проверьте доступность сервера командой `ping IP_СЕРВЕРА`.
4. Проверьте, что адрес начинается с `http://`, а не `https://`.
5. Убедитесь, что TCP-порт `3000` разрешён firewall только для локальной подсети.
6. Проверьте, что Wi-Fi не использует гостевой режим или изоляцию клиентов.
7. Убедитесь, что VPN не перенаправляет локальный трафик.
8. Посмотрите журнал: `docker compose logs --tail=200 logistics-mvp`.

Пример для Linux с UFW и подсетью `10.18.2.0/24`:

```bash
sudo ufw allow from 10.18.2.0/24 to any port 3000 proto tcp
```

В Windows разрешите входящие TCP-подключения к порту `3000` только для профиля частной/доменной сети. В macOS разрешите входящие подключения Docker Desktop.

## 9. PostgreSQL и администрирование

PostgreSQL не публикует порт на сервер и недоступен обычным пользователям локальной сети. Для запросов используйте `docker compose exec postgres psql ...` на самом сервере.

Резервную копию следует создавать на сервере:

```bash
docker compose exec -T postgres pg_dump -U logistics -d logistics_mvp > logistics_mvp_backup.sql
```

Основные данные находятся в Docker volume `postgres-data`. Команда `docker compose down` их сохраняет. Команда `docker compose down -v` удаляет базу и не должна использоваться при обычном обслуживании.

## 10. Проверка отсутствия внешних ресурсов

В HTML нет CDN, Google Fonts, внешних скриптов или внешних таблиц стилей. Единственный AI-вызов направляется на локальный контейнер Ollama по адресу `http://ollama:11434` внутри Docker-сети.

Проверка исходников:

```bash
rg -n -i "https?://|googleapis|gstatic|cdnjs|jsdelivr|unpkg" public server.js
```

Команда не должна находить внешние URL. В Network-панели браузера запросы должны идти только на IP сервера.
