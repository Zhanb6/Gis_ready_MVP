# Безопасность

Не публикуйте найденные уязвимости в открытых Issues. Передайте описание владельцу репозитория приватным каналом и укажите шаги воспроизведения, возможное влияние и версию приложения.

Никогда не добавляйте в Git файлы `.env`, резервные копии базы, закрытые ключи, сертификаты или реальные пользовательские данные. Перед публикацией запускайте проверку:

```bash
git status --ignored
rg -n -uu -g '!.env' -g '!.env.*' -g '!vendor/node_modules/**' -i "password=|secret=|api[_-]?key|BEGIN .*PRIVATE KEY"
```

Для рабочей установки используйте HTTPS на доверенном обратном прокси и установите `COOKIE_SECURE=true`. Доступ к порту приложения ограничивайте доверенной локальной сетью.
